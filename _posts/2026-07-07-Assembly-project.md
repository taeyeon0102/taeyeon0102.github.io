## 1. 서론 및 핵심 아이디어 (Introduction and Main Idea)
이 프로젝트의 핵심 아이디어는 x86 어셈블리(Assembly) 언어를 사용하여 기능적이고 상호작용이 가능한 도서관 좌석 예약 시스템을 구축하는 것입니다. 단순한 CRUD 프로그램을 넘어, 본 프로젝트는 배열 구조 관리, 여러 사용자 세션 간의 데이터 영속성(data persistence) 유지, 타이머를 위한 하드웨어 인터럽트(hardware interrupts) 활용 등 실용적인 로우레벨(low-level) 프로그래밍 과제를 해결하는 데 중점을 두었습니다. 이 시스템을 통해 다수의 학생이 로그인하여 사용 가능한 좌석을 조회하고, 좌석을 예약한 뒤 안전하게 로그아웃할 수 있습니다. 또한, 도서관 전체 좌석 상태를 조회하고 일과 종료 시 메모리를 초기화할 수 있는 관리자(Admin) 모드가 포함되어 있습니다.

---

## 2. 프로젝트 목표 (Project Goals)
16비트 MS-DOS 환경에서 시스템이 원활하게 작동하도록 다음 목표에 집중했습니다.

* **데이터 영속성 (Data Persistence):** 사용자가 로그아웃하고 다른 사용자가 로그인할 때, `.DATA` 세그먼트의 변수(예: 좌석 예약 상태)가 예기치 않게 초기화되지 않도록 보장합니다.
* **예약 유효성 검사 (Booking Validation):** 중복 예약을 방지합니다. 사용자 1이 1번 좌석을 예약하면 시스템은 메모리 배열을 확인하여 사용자 2가 해당 좌석을 예약하지 못하도록 차단해야 합니다.
* **사용자 경험(UX) 개선:** 정적인 "아무 키나 누르시오(Press any key to continue)" 화면을 BIOS 타이머 인터럽트를 활용한 자동 5초 카운트다운 기능으로 대체했습니다.
* **메모리 관리 (Memory Management):** 관리자 기능을 구현하여 메모리 배열을 루프(loop)로 순회하며 모든 좌석 값을 0으로 초기화합니다.

## 3. 설계 및 구조 (Design and Structure)

### 3.1 메모리 할당 및 데이터 명세 (Memory Allocation and Data Specifications)
본 시스템은 16비트 데이터 세그먼트(Data Segment) 내의 정밀한 로우레벨 메모리 할당을 통해 상태를 관리합니다. 충돌을 방지하고 레지스터 사용을 최적화하기 위해 데이터 타입을 다음과 같이 엄격하게 정의했습니다.

| 변수명 (Variable Name) | 데이터 타입 (Data Type) | 초기값 (Initial Value) | 메모리 목적 / 설명 (Memory Purpose / Description) |
| :--- | :--- | :--- | :--- |
| **seat_status** | DB (Byte) | 7 DUP(0) | 이진 점유 상태를 추적하는 전역 배열 (0: 빈 좌석, 1: 사용 중)  |
| **name_** | DB (Byte) | 8 DUP(?) | 런타임 사용자 이름 인증을 위한 입력 버퍼 |
| **pass_** | DB (Byte) | 5 DUP(?) | 런타임 비밀번호 검증을 위한 입력 버퍼 |
| **user1_booked** | DB (Byte) | 0 | 사용자 1이 예약한 특정 좌석 인덱스를 추적하는 포인터  |
| **booking_hours** | DB (Byte) | 0 | 좌석 대여 시간 제한 검증을 위한 임시 저장소 |

### 3.2 시스템 아키텍처 및 메뉴 인터페이스 (System Architecture and Menu Interface)
시스템은 직관적인 메뉴 구동(menu-driven) 방식으로 설계되었습니다. 데이터 관리를 위해 프로그램은 0 기반 배열(0-based arrays)을 사용합니다. `seat_status` 배열은 7개 좌석의 예약 가능 여부를 추적합니다 (0은 빈 좌석, 1은 사용 중). 각 사용자에 대해 긴 if-else 블록을 작성하는 대신, 사용자 전용 변수(`user1_booked`, `user2_booked`)를 사용하여 선택한 좌석의 인덱스를 간단히 저장하도록 처리했습니다. 이를 통해 코드가 훨씬 간결해지고 확장성(scalability)이 향상되었습니다.

## 4. 구현 세부 사항 (Implementation Details)
이 섹션에서는 어셈블리 언어로 핵심 로직을 어떻게 구현했는지 설명합니다.

* **단계 1: 좌석 할당을 위한 배열 인덱싱 (Using Array Indexing for Seat Allocation):** 사용자가 좌석 번호(ASCII '1'-'7')를 입력하면 프로그램은 이를 정수로 변환하고 배열 내의 정확한 메모리 주소를 찾는 데 사용합니다. 어레이가 인덱스 0부터 시작하므로 1을 빼주는 연산(`dec si`)을 수행하며, `seat_status[si]`의 값을 확인해 1(사용 중)과 같을 경우 `seat_taken` 에러로 분기하도록 구현했습니다.
* **단계 2: 5초 카운트다운 하드웨어 타이머 (The 5-Second Countdown (Hardware Timer)):** UI를 실제 키오스크처럼 구성하기 위해 자동 카운트다운 함수(`countdown_5s`)를 구현했습니다. 1초의 시스템 지연을 구현하기 위해 BIOS 대기 인터럽트(BIOS Wait Interrupt, `INT 15h`, `AH=86h`)를 사용하였으며, 상위 및 하위 16비트 레지스터에 1,000,000 마이크로초를 나누어 할당했습니다.
* **단계 3: 관리자 초기화 기능 (The Admin Reset Function):** `admin_reset` 프로시저는 데이터 세그먼트를 직접 조작하는 방식을 보여줍니다. [cite_start]이 기능은 루프(`mov cx, 7`)를 사용하여 `seat_status` 배열을 순회하며, 각 인덱스를 수동으로 0으로 덮어써서 다음 날을 위해 예약 상태를 안전하게 초기화합니다.

## 5. 사용된 도구 및 소프트웨어 (Tools and Software Used)

### 5.1 기술 환경 세부 정보 (Technical Environment Details)
* **언어 (x86 Assembly):** CPU 아키텍처를 직접 제어하고 로우레벨 메모리 세그먼트 조작을 수행하기 위해 사용되었습니다.
* **어셈블러 및 링커 (TASM / TLINK):** 16비트 Intel 8086 구조화된 프로그램을 어셈블하기 위한 신뢰할 수 있는 업계 표준 툴체인(toolchain)으로 활용되었습니다.
* **에뮬레이션 레이어 (DOSBox):** 최신 64비트 운영 체제에서 하드웨어적으로 정확한 16비트 Intel 리얼 모드(real-mode) 환경을 시뮬레이션하여 하드웨어 인터럽트(`INT 15h` 및 `INT 21h`)가 제대로 실행되도록 하기 위해 사용되었습니다.

### 5.2 시스템 검증 및 테스트 케이스 (System Verification and Test Cases)
시스템의 안정성을 평가하고 다양한 상태에서 모든 예외 처리 루틴이 올바르게 기능하는지 확인하기 위해 다음 테스트 케이스를 실행했습니다.

* **테스트 케이스 1: 다중 세션 데이터 영속성** 
    * **입력/동작:** 사용자 1이 로그인하여 1번 좌석을 예약하고 로그아웃합니다[cite: 63]. 사용자 2가 로그인하여 좌석 상태 조회를 요청합니다.
    * **예상 결과:** 시스템이 사용자 2의 세션 중에도 전역 메모리에 1번 좌석을 사용 중(`[1]`) 상태로 성공적으로 유지합니다.
    * **상태:** 통과 (PASSED).
* **테스트 케이스 2: 중복 예약 방지 (경쟁 상태 시뮬레이션)** 
    * **입력/동작:** 사용자 2가 이미 사용자 1이 예약한 1번 좌석을 선택하려고 시도합니다.
    * **예상 결과:** 배열 오프셋(offset) 검사를 통해 해당 주소에 1이 저장되어 있음을 식별합니다[cite: 69]. [cite_start]실행 흐름이 `seat_taken`으로 분기하여 오류 프롬프트를 표시합니다.
    * **상태:** 통과 (PASSED)[cite: 70].
* **테스트 케이스 3: 관리자 전역 초기화 루프**
    * **입력/동작:** 관리자가 인증 후 옵션 2(Reset Library)를 선택합니다.
    * **예상 결과:** 하드웨어 루프가 성공적으로 7회 반복 실행되어 `seat_status` 배열을 다시 0으로 지우고 모든 활성 예약을 초기화합니다[cite: 73].
    * **상태:** 통과 (PASSED).

## 7. 결론 및 핵심 시사점 (Conclusion and Key Findings)
이 프로젝트를 통해 메모리 주소와 전역 변수를 적절하게 다루는 방법을 배웠습니다. 가장 큰 난관 중 하나는 사용자가 로그아웃할 때 예약된 모든 좌석이 빈 좌석으로 초기화되는 "리셋 버그(reset bug)"였습니다. 이는 시스템이 `MAIN PROC`의 맨 처음으로 점프하여, 초기 `init_seats` 루프가 데이터를 덮어쓰기 때문에 발생한다는 것을 파악했습니다. 불필요한 초기화 루프를 제거하고 로그아웃 시 프로그램의 시작 지점이 아닌 `taking_input` 라벨로 분기하도록 수정하여 이를 해결했습니다. 본 프로젝트는 어셈블리 상에서의 메모리 영속성(memory persistence), 배열 인덱싱, BIOS 하드웨어 인터럽트 활용에 대한 이해를 크게 향상시켰습니다.
